# AC-001 自动化质量门

## 每次交付必须执行

```bash
./scripts/verify.sh
```

该脚本必须成功完成：

- 资料库必需目录、索引、相对链接、根目录清洁度和敏感内容检查；
- Go 全包竞态测试、普通测试和 `vet`；
- Go 调用路径漏洞扫描；
- 前端 TypeScript、ESLint、依赖审计和生产契约测试；
- SPA 构建；
- 前端嵌入 Go 的单二进制构建；
- 交付物和 Secret 忽略规则检查。

独立进程黑盒验收：

```bash
./scripts/acceptance-local.sh
```

必须验证生产模式启动、存活/就绪、鉴权状态码、API 元数据、schema v21 和 SQLite 在线备份完整性。该脚本不得连接真实节点。

Docker 可用时执行：

```bash
./scripts/acceptance-container.sh
```

必须验证镜像构建、非 root、能力限制、健康检查、系统设置与 Secret 权限、容器重建持久化、在线备份和全新卷离线恢复。Docker Scout 可用时阻断 Critical/High 漏洞。

## 变更类型对应门禁

| 变更 | 最低验证 |
|---|---|
| 文档 | 文档结构、相对链接、敏感词和事实一致性检查 |
| 前端样式或交互 | `verify.sh`，并按请求进行浏览器回归 |
| API、Store、认证 | `verify.sh` + `acceptance-local.sh` |
| Docker、配置、备份 | 三个脚本全部执行 |
| Web 代理或 WebSSH | 三个脚本 + 协议集成测试 + 授权真实设备回归 |
| 节点适配、发现或转发 | 三个脚本 + 隔离 Client 真实验收 |
| schema 迁移 | 新旧库升级、备份、恢复和回滚边界验证 |

测试失败不能通过降低断言、改写为占位数据或跳过安全检查解决。确属测试过时时，必须先证明产品决策已变更。
