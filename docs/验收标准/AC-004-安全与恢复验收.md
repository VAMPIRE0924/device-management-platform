# AC-004 安全与恢复验收

## 身份与权限

- 未认证 API 返回 401，未知 API 返回 404。
- 系统管理员、项目管理员、运维和临时用户只能访问其后端权限允许的资源。
- 首次登录流程不可跳过；MFA 挑战过期、重复消费和超限尝试被拒绝。
- 恢复码一次性消费；管理员不能在自己的活动会话中重置自身 MFA。
- 迁移撤销旧登录会话，不改变既有密码哈希和业务权限。

## Secret 与传输

- API 不回显节点、SOCKS、SSH、SMTP、TLS 私钥或 MFA 主密钥内容；SQLite 只保存不含明文的节点凭据 AES-GCM 密文。
- 控制面 Cookie、Authorization、CSRF 和伪造转发头不发送给设备。
- 客户端不能伪造 wildcard 内部标记绕过路径和 Cookie 隔离。
- 设备 HTTPS Endpoint 按内网运维模型统一允许自签证书，不得放宽平台自身 TLS 或节点 API TLS。
- SSH 主机指纹配置后必须严格匹配；未配置时不存在另外的降低安全开关。
- 生产非回环监听不能关闭安全 Cookie，访问域名不能使用明文 HTTP。

## 容器

- 进程 uid/gid 为 10001，数据卷可写，二进制目录不可写。
- 删除全部 Linux capabilities，启用 `no-new-privileges`。
- Secret 文件和网页覆盖配置权限为 0600，API 不回显 SMTP 密码。
- 重建容器后数据库和网页覆盖配置保持。
- 镜像漏洞扫描无 Critical/High；发布策略要求更严格时按策略阻断。

## 备份与恢复

- 在线备份的 `pragma integrity_check` 为 `ok`，schema 与当前支持版本一致。
- 离线恢复拒绝损坏、过新 schema 或活动 WAL 状态。
- 覆盖已有数据库前创建可恢复快照。
- 恢复到全新卷后核心对象数量和权限一致。
- SQLite 与 MFA 主密钥、节点凭据主密钥 `i5cloud.secrets.key`、配置和 Secret 成组恢复；缺失密钥时走受控重置，不降低认证策略。

## 审计

安全设置、用户/MFA 管理、节点/项目/设备变更、扫描、访问会话、转发和恢复操作必须包含操作者、资源、请求 ID、来源 IP、结果和时间。审计不得保存密码、私钥、验证码、恢复码、SOCKS 凭据或终端内容。
