# 本地开发与发布

## 分支与镜像渠道

| Git 分支或标签 | 用途 | Docker 标签 |
|---|---|---|
| `dev` | 日常开发、修复和集成测试 | `dev` |
| `main` | 已通过验证的最新正式代码 | 不直接按分支发布 |
| `vX.Y.Z` | 指向当前 `main` 正式提交的版本标签 | 同名 `vX.Y.Z` 和 `latest` |

不得从 `dev`、功能分支或未打正式标签的提交更新 `latest`。正式镜像工作流会校验版本号、Git 标签及其提交是否与当前 `main` 完全一致；`dev` 分支工作流只更新 Docker `dev` 标签。

生产环境固定 `vX.Y.Z`，或在接受自动升级时使用 `latest`。`dev` 随测试分支推送变化，不承诺数据迁移兼容性和运行稳定性，不得连接生产数据目录。

## 本地环境

- Go `1.26.6`；
- Node.js `22.13` 或更高版本；
- Docker Engine 24+ 与 Docker Compose v2；
- 本地黑盒验收需要 `curl` 和 `sqlite3`；
- 容器验收还需要 `openssl`，Docker Scout 可选。

首次准备前端依赖：

```bash
cd frontend
npm ci
cd ..
```

## 构建与验证

完整验证命令：

```bash
./scripts/verify.sh
./scripts/acceptance-local.sh
./scripts/acceptance-container.sh
```

`verify.sh` 会执行文档检查、Go race 测试、依赖漏洞检查、前端类型检查与 lint、14 项渲染契约测试、SPA 构建和嵌入式单二进制构建。

仅构建本地二进制：

```bash
DMP_BUILD_VERSION=dev ./scripts/build-local.sh
```

## 本地运行与 Web 反代

不要使用面板路径 `/access/web/...` 测试 Web 服务。当前实现只接受随机子域名，并要求面板域名与反代泛域名严格分离。

以下示例使用 `nip.io` 将两个不同域名都解析到 `127.0.0.1`：

```bash
local_data_dir="$(mktemp -d /tmp/device-management-platform-dev.XXXXXX)"

DMP_MODE=dev \
DMP_LISTEN_ADDR=127.0.0.1:18088 \
DMP_HTTPS_LISTEN_ADDR=127.0.0.1:18443 \
DMP_DATA_DIR="$local_data_dir" \
DMP_DB_PATH="$local_data_dir/platform.db" \
DMP_PANEL_DOMAIN=dmp.127.0.0.1.nip.io \
DMP_ACCESS_DOMAIN=console.127.0.0.1.nip.io \
DMP_ACCESS_SCHEME=http \
./backend/bin/device-management-platform serve
```

面板地址为 `http://dmp.127.0.0.1.nip.io:18088/`；Web 会话地址形如 `http://web-k7m2x9p4.console.127.0.0.1.nip.io:18088/`。每次新建 Web 访问会话都会获得新的 8 位随机前缀。

创建访问会话时平台启动对应 NPS SOCKS 通道。Web、WebSocket 和 WebSSH 的真实流量更新活动时间；平台会话空闲上限与 NPS 的 30 分钟无流量回收保持一致。SOCKS 拨号失败不会再次启动旧通道，过期后应从面板创建新访问会话。

## 正式发布检查表

1. 所有更改先提交并推送到 `dev`，确认 `Verify` 和 `Publish development Docker image` 成功。
2. 完成人工浏览器验收，特别检查多个随机 Web 子域、Cookie、重定向、WebSocket、WebSSH、Host 隔离和会话终止。
3. 更新 `VERSION`、前端版本和 `CHANGELOG.md`；更新记录保持真实，不提前声明尚未完成的发布。
4. 将已经验证的 `dev` 提交纳入 `main`，不要在 `main` 上继续调试或追加临时补丁。
5. 在当前 `main` 提交创建 `vX.Y.Z` 标签和 GitHub Release。
6. 手动运行正式 Docker 工作流；确认 `vX.Y.Z` 与 `latest` 的多架构摘要完全一致。
7. 通知部署人员手动拉取新的正式镜像。平台不会自动替换生产容器。

发布后至少核对：

```bash
git ls-remote origin refs/heads/main refs/heads/dev refs/tags/vX.Y.Z 'refs/tags/vX.Y.Z^{}'
docker buildx imagetools inspect vampirerune/device-management-platform:vX.Y.Z
docker buildx imagetools inspect vampirerune/device-management-platform:latest
```
