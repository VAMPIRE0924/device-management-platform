# DOC-001 文档治理规范

## 目标

资料库必须让没有聊天上下文的开发者或自动化代理在一次读取后知道：产品允许什么、当前实现到哪里、什么算完成、哪些事情仍受阻、修改后需要更新哪里。

## 文档类型

- 产品决策：长期规范。使用 `PD-NNN`，状态为提议、已接受、已替代或已废弃。
- 验收标准：完成定义。使用 `AC-NNN`，只写可验证条件和当前证据边界。
- 架构设计：描述当前实现，不声明规划能力已完成。
- 部署运维：记录可重复部署、配置、备份、恢复和安全流程。
- 开发日志：按 `YYYY-MM.md` 追加事实、验证和遗留问题，不承担规范职责。
- 文档规范：定义资料库自身的维护和自动开发流程。

## 命名与链接

- 每个目录必须有 `README.md` 索引。
- 规范文档使用稳定 ID；标题或文件名变化时保留 ID。
- 文档内部使用相对链接，不引用本机绝对路径。
- 代码文件可写仓库相对路径，不记录临时目录、进程 ID 或短期会话令牌。
- 不创建“最终版、最新版、新版2”一类文件；版本变化通过状态、日期和开发日志表达。

## 状态与事实

- “已实现”必须能定位代码或测试。
- “已验证”必须有自动化命令或真实协议证据。
- “计划、建议、可选”不得写入已完成清单。
- 外部 DNS、证书、SMTP、凭据轮换和真实环境授权必须保留为门禁，直到有证据关闭。
- 开发日志中的历史数字和地址不能自动成为未来授权。

## 更新规则

| 变更 | 必须更新 |
|---|---|
| 产品边界或导航变化 | 产品决策、功能验收矩阵、开发日志 |
| API、schema 或数据约束变化 | 架构设计、验收标准、开发日志 |
| 配置、容器、备份变化 | 部署运维、安全验收、开发日志 |
| 真实环境验收 | AC-003、开发日志；不得写入秘密 |
| 缺陷修复 | 相关验收标准、自动化回归、开发日志 |
| 仅内部重构 | 开发日志；行为不变时无需改产品决策 |

## 清理规则

文档满足以下任一条件时合并或删除：

- 与规范文档重复且没有独立历史价值；
- 把过去计划描述为当前待办，实际已经完成；
- 状态、命令、schema 或页面结构已过时；
- 依赖聊天上下文才能理解；
- 含秘密、短期会话、临时进程或不可复用环境信息。

删除前把仍有效的决策、验收证据和未关闭事项迁移到对应目录，并在迁移记录写明去向。

## 安全

禁止写入密码、令牌、私钥、验证码、恢复码、公共连接密钥、SMTP 密码和可直接复用的认证 Cookie。真实内网地址只在验收需要时记录，并明确它不是后续默认授权。
