# DOC-002 自动开发工作流

## 1. 启动

1. 按资料库首页顺序读取产品决策、验收标准、本文和最新开发日志。
2. 检查工作区和当前运行状态，保留已有修改，不执行破坏性重置。
3. 把用户请求映射到产品决策 ID 和验收项 ID。
4. 判断任务是只读审查、诊断、实现、真实验收还是部署；不能把诊断请求扩大成外部写操作。
5. 运行与任务相关的最小基线测试。基线失败时先记录现有失败，避免把旧问题归因于新修改。

## 2. 计划

计划必须包含：

- 用户可见目标；
- 受影响组件和数据；
- 权限、安全、迁移和回滚边界；
- 自动化测试；
- 是否需要真实节点、浏览器、SMTP、DNS 或证书；
- 需要更新的资料。

能从代码、配置和资料中确定的信息自行查证。只有缺失选择会显著改变结果或需要新增授权时才询问用户。

## 3. 实现

- 以现有架构、包管理器、锁文件、配置和迁移方式为基础，不另建平行实现。
- 前后端状态必须来自真实 API；禁止为“看起来可用”增加不可区分的假成功。
- 枚举和关联对象使用选择控件；秘密使用引用，不接收或回显明文。
- 任何设备、发现和转发目标都在后端执行项目 CIDR 校验。
- Web 访问不能创建端口转发；WebSSH 和原生转发遵守 PD-003。
- schema 变化必须新增向前迁移，保留旧数据并验证备份恢复。
- 真实节点操作只限用户明确授权对象，并在结束时恢复原状态。

## 4. 验证

按 [AC-001](../验收标准/AC-001-自动化质量门.md) 选择测试。至少验证正常路径、失败路径、权限、刷新/重试、撤销/过期和数据持久化中与本次变更相关的部分。

真实协议能力不能只用 Mock 宣布完成：

- Web：真实页面、资源、重定向、Cookie/API 或 WebSocket；
- SSH：真实握手、主机指纹、认证、终端和撤销；
- 发现：真实协议证据而不是 SOCKS CONNECT；
- 转发：真实监听、数据响应、停止、重启和删除；
- SMTP：STARTTLS/隐式 TLS、投递和失败策略；
- 恢复：独立数据目录或全新卷。

## 5. 文档与交付

完成前：

1. 更新受影响的规范文档；规范没有变化时不要为了制造改动而改写。
2. 在当月开发日志追加日期、范围、关键决策、修改、验证、遗留和最终外部状态。
3. 未完成事项使用“受阻/待验收”并写清解除条件。
4. 最终答复先给结果，再列验证和仍需用户配合的最小事项。

## 6. 自动继续与停止条件

在授权范围内，只要存在安全、可验证且不需要新授权的工作，就继续推进。遇到以下情况停止并请求用户：

- 要操作未授权客户网络、Client、设备或外部账号；
- 需要新的生产凭据、DNS、证书、SMTP 或防火墙变更；
- 数据迁移存在不可逆选择且资料无法确定；
- 权限或保护机制拒绝操作；
- 用户目标相互冲突且会改变产品边界。

不得通过关闭 TLS、跳过认证、扩大扫描、输出 Secret 或删除数据绕过阻塞。
