6. 检查实际代码、数据库迁移、配置模板和脚本；文档描述“已实现”但代码不存在时，以代码为事实并修正文档。

## 资料优先级

发生冲突时按以下顺序处理：

1. 安全边界、数据迁移和真实节点操作授权；不明确时停止破坏性或外部写操作。
2. 当前代码、数据库迁移、API 合同和配置校验代表“系统实际上做什么”。
3. 已接受的产品决策代表“系统应当做什么”。
4. 验收标准代表“什么条件下才算完成”。
5. 架构与部署文档解释实现方式。
6. 开发日志只记录历史，不覆盖当前决策。

发现 2–4 项不一致时，不得静默选择其一：应修复实现或更新决策，并在开发日志记录原因和验证证据。

## 当前不可突破的产品边界

- 品牌和界面统一使用 **I5CLOUD**；与用户操作直接相关的 Client、SOCKS 和 NPS 实时状态可以如实标注。
- 设备 Web 后台只能通过平台 Web 网关和项目托管 SOCKS 访问，不能为 Web 新建端口转发。
- WebSSH 由平台 WebSocket 网关经项目托管 SOCKS 连接设备 SSH；SSH 端口可配置，不限定为 22。
- SSH、RDP、RTSP、数据库和其他原生客户端服务可以按需使用端口转发。
- 一台设备可拥有多个具名 Web、SSH 或原生服务 Endpoint。
- 项目扫描 CIDR 必须显式配置；它只限制设备发现，不限制已登记设备的访问。
- 自动发现只能扫描项目保存的 CIDR 子集和端口，只有协议响应证据可以标记为已验证。
- 浏览器不能获得节点管理凭据、SOCKS 凭据、SMTP 密码、私钥或设备保存凭据。
- 当前前端信息架构已冻结；新增主菜单、改变对象层级或改变 Web 网络路径必须新增产品决策。

## 当前实现基线

- Go 单进程控制面，React/TypeScript SPA 嵌入同一二进制。
- SQLite schema v21，支持版本化迁移、在线一致性备份、节点与 SSH 密码密文持久化和带恢复前快照的离线恢复。
- 支持节点、项目、Client、托管通道、设备多 Endpoint、发现、端口转发、用户、策略、门户、监控和审计。
- 支持首次登录改密、验证邮箱、TOTP/邮箱 MFA、恢复码、管理员重置和离线恢复；是否启用 MFA 由正式部署环境配置。
- 本地质量门、独立进程黑盒验收和非 root Docker 验收已通过。
- 当前真实 Web、WebSSH、发现和临时转发已完成受控验证；正式部署仍须按环境完成 wildcard DNS、可信证书、SMTP 投递、凭据轮换和备份恢复演练。

## 常用验证入口

```bash
./scripts/verify.sh
./scripts/acceptance-local.sh
./scripts/acceptance-container.sh
```

真实节点写操作不属于常规自动化门禁。只有用户明确授权测试对象、网段和动作后才能执行，并必须恢复原状态。
