# 安全边界

本文描述当前正式版必须保持的访问边界。实现或部署变更不得削弱这些约束。

## 平台会话与远程访问

- Web 与 WebSSH 访问只能由已登录的平台用户创建；内部 API 令牌不能签发浏览器远程访问。
- 访问会话绑定用户、平台登录会话、项目、设备端点、来源地址与有效期；其到期时间不得晚于创建它的平台登录会话绝对期限，并在每次请求时复核平台会话的闲置期限。
- 子域名标识由平台登录会话和设备入口派生：同一登录会话重新打开同一入口时保持稳定，退出、超时或切换用户后变更。它只负责定位访问会话，不是授权凭证。首次进入还必须交换每次新签发的一次性授权；交换完成后使用 `HttpOnly`、`SameSite=Strict`、Host-only 的短期 Cookie。
- 平台登录被注销、闲置超时、达到绝对期限、用户被停用或访问会话被撤销后，既有反代和 WebSSH 请求均被拒绝。

## 用户、项目与设备隔离

- 非系统管理员只能读取其明确所属的项目；临时用户还必须命中有效访问策略与能力。
- 反代路由从数据库中已绑定的 `项目 → 设备 → Endpoint` 解析，访问会话中的项目与 Endpoint 必须再次联表一致。
- 客户端不能在访问 URL 或请求参数中指定目标 IP、端口、SOCKS 节点或上游协议，因此反代不能退化为任意地址开放代理。
- SOCKS 路由只从项目绑定的接入节点和 Client ID 取得。

## HTTP、Cookie、WebSocket 与重定向

- 进入上游前移除平台 Cookie、Authorization、CSRF、`Forwarded`、`X-Forwarded-*` 与 `X-Real-IP`，避免控制面凭据泄漏到设备。
- 上游 Cookie 删除 `Domain` 并限制到当前访问路径；保留名称若与平台 Cookie 冲突则直接丢弃。
- 上游重定向只允许留在当前设备会话；跨来源地址会被收敛到访问根路径，不能把浏览器导向另一个设备或任意公网地址。
- 每个 WebSocket 连接复用同一访问会话校验和固定上游路由，不能通过 `Host`、`Origin` 或转发头改写目标。
- 未配置为可信反向代理的来源，其伪造转发头会在进入鉴权前被清除。

## 凭据与审计

- 节点认证密码与 SSH 密码使用 `/data` 中独立主密钥加密后写入数据库；密码字段保存后不回显。
- 临时 WebSSH 用户名和密码只存在于该次连接内存中，不写入数据库。
- 审计接口不读取请求体。审计存储层还会递归清除名称包含 password、secret、token、credential、private key、authorization、cookie 等敏感字段；格式错误的元数据不会原样落库。
- TLS 证书和私钥只读。平台不复制、不修改、不改变宿主机证书权限。

## 验证清单

发布前至少验证：无登录访问随机子域名被拒绝；一次性授权不能重放；跨项目 Endpoint 被拒绝；伪造转发头无效；跨来源重定向被收敛；审计导出不包含测试密码；登录闲置超时会同步终止远程访问。
