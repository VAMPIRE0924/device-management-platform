# 登录安全与双重认证

## 目标

双重认证由基础配置文件或系统设置统一控制。启用后，首次管理员、迁移用户和管理员新建用户均必须完成首次登录向导；未完成时只能访问向导接口。

支持：

- TOTP：身份验证器扫描二维码，服务端保存 AES-GCM 加密密钥。
- 邮箱：向已验证邮箱发送短期验证码，数据库只保存 HMAC。
- 恢复码：只在绑定时显示一次，数据库只存哈希，用过即失效。

## 首次登录

1. 使用初始密码登录。
2. 设置与初始密码不同的新密码。
3. 填写邮箱并通过验证码完成验证。
4. 选择 TOTP 或邮箱 MFA。
5. 完成对应绑定，保存恢复码后创建正式会话。

日常登录先验证密码，再提交已绑定方式的验证码或一个未使用的恢复码。过期、重复使用、超过尝试次数或已消费挑战均被拒绝。

## 配置

关键字段：

| 字段 | 含义 |
|---|---|
| `mfa_enabled` | 是否强制首次登录和日常 MFA |
| `mfa_methods` | `totp,email` 中允许的方法 |
| `mfa_key_file` | 加密 TOTP 密钥的 32 字节主密钥 |
| `mfa_email_code_ttl` | 邮箱验证码有效期，允许 1–30 分钟 |
| `smtp_host` / `smtp_port` | 发件服务器 |
| `smtp_username` / `smtp_password_file` | SMTP 身份和密码文件 |
| `smtp_from` | 发件人名称和地址 |
| `tls_cert_file` / `tls_key_file` | 面板域名的证书和私钥文件路径 |
| `access_tls_cert_file` / `access_tls_key_file` | 反代泛域名使用独立证书时的文件路径 |
| `access_http_port` / `access_https_port` | `0/0` 复用面板端口；非零时为独立反代端口 |
| `settings_override_file` | 网页设置覆盖文件 |

SMTP 连接始终加密：端口 465 自动使用隐式 TLS，其余端口使用 STARTTLS；平台不支持明文 SMTP。

启用 MFA 后即使只允许 TOTP，首次登录仍需验证邮箱，因此必须先配置可用 SMTP。生产模式不允许对非回环 SMTP 使用明文传输。

## 迁移与恢复

- schema v11 保留用户名、密码哈希、角色和业务权限，将既有用户标记为需要首次登录并撤销旧会话。
- 管理员可重置其他用户，不能在自己的活动会话中重置自己。
- 运维人员可在受控主机执行 `device-management-platform mfa-reset <用户名>`；该命令清除 MFA、撤销会话并要求重新完成首次登录，不修改密码。
- 平台 API 令牌也可作为管理员恢复路径，必须独立保管并限制来源。

SQLite 与 `mfa_key_file` 必须成对恢复。密钥错配时应逐个重置并重新绑定，不得通过关闭生产 MFA 绕过。
