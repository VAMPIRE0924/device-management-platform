# 构建、部署与数据备份

## 交付形态

- 前端构建为静态资源并嵌入 Go 二进制。
- SQLite 默认位于 `/data/platform.db`，只允许单实例写入。
- Docker 最终镜像只包含二进制、CA 和时区数据，以非 root 用户运行。

本地构建与运行：

```bash
./scripts/build-local.sh
./backend/bin/device-management-platform serve
```

Docker 部署：

```bash
docker compose pull
docker compose up -d
```

Compose 默认拉取 `vampirerune/device-management-platform:latest`。需要固定版本时，可在 `.env` 中设置 `DMP_IMAGE=vampirerune/device-management-platform:v1.0.11`。`latest` 和 `vX.Y.Z` 只用于正式版本，`dev` 仅用于测试。完整部署步骤见 [Docker 正式部署](./Docker部署.md)。

健康检查使用 `device-management-platform healthcheck`，始终探测容器内的 HTTP 监听，不依赖证书配置。

## 配置与 Secret

本地二进制部署可以复制 `conf/device-management-platform.conf.example` 作为基础配置。Docker 快速部署不需要该文件，常用设置可在网页中完成。环境变量优先于基础配置，基础配置优先于网页覆盖配置。

生产要求：

- 内部 API 令牌在首次启动时自动生成到 `/data/api.token`；SMTP 密码、TLS 私钥、MFA 主密钥、节点/SSH 凭据主密钥和 SSH 私钥使用独立受限文件。
- Docker 中 Secret 目录只读挂载，文件必须可由 uid 10001 读取且不向其他用户开放。
- 平台和访问子域名使用 HTTPS；安全 Cookie 保持启用。
- Web 访问必须配置与面板域名分离的 wildcard DNS、可信证书、反向代理和 `access_domain`；平台不提供同源路径代理回退。
- 完成 SMTP 配置、恢复演练和主密钥备份后再开启 MFA。

## 备份

系统管理员通过平台接口下载 SQLite 一致性快照。备份包含业务配置、密码哈希、凭据引用和节点凭据密文，按敏感数据保护。

必须与 SQLite 成组备份但不会包含在下载文件中的资产：

- MFA 主密钥；
- 内部 API 令牌 `/data/api.token`；
- 数据目录中的节点凭据主密钥 `credentials.key`；
- 基础配置和网页覆盖配置；
- SMTP 密码；
- TLS 证书私钥；
- SSH 配置引用的服务器本地私钥文件。

## 恢复

恢复必须停服：

```bash
DMP_DB_PATH=/data/platform.db ./device-management-platform restore /backup/device-management-platform-backup.db
```

恢复命令校验 SQLite 完整性和 schema，在目标目录暂存并复核；已有数据库先生成 `.before-restore-<UTC>.db`，再原子替换并执行迁移。存在活动 WAL 共享内存文件时拒绝恢复。

MFA 主密钥和 `credentials.key` 必须与数据库快照匹配。MFA 密钥丢失时走受控重置；节点凭据主密钥丢失时密文无法恢复，需重新输入节点密码，不得通过降低安全策略绕过。
