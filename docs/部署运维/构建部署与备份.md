# 构建、部署与数据备份

## 交付形态

- 前端构建为静态资源并嵌入 Go 二进制。
- SQLite 默认位于 `/data/platform.db`，只允许单实例写入。
- Docker 最终镜像只包含二进制、CA 和时区数据，以非 root 用户运行。

本地构建与运行：

```bash
./scripts/build-local.sh
./backend/bin/device-management-platform serve
```

Docker：

```bash
cp .env.example .env
cp conf/device-management-platform.conf.example conf/device-management-platform.conf
umask 077
openssl rand -hex 32 > secrets/api_token
openssl rand -hex 24 > secrets/setup_token
docker compose pull
docker compose up -d
```

Compose 默认拉取 `vampirerune/device-management-platform:latest`。正式环境应在 `.env` 固定完整版本，例如 `vampirerune/device-management-platform:v1.0.0`。完整部署步骤见 [Docker 正式部署](./Docker部署.md)。

健康检查使用 `device-management-platform healthcheck`，会按配置选择 HTTP 或 HTTPS。仅本机健康探测可对本机自签证书放宽校验，不影响节点和远程访问的 TLS 策略。

## 配置与 Secret

基础配置模板为 `conf/device-management-platform.conf.example`；复制生成的 `conf/device-management-platform.conf` 不会提交到 Git。网页可编辑项写入 `settings_override_file`；环境变量优先于部署配置，部署配置优先于网页覆盖配置。

生产要求：

- API 令牌、初始化令牌、SMTP 密码、TLS 私钥、MFA 主密钥、节点/SSH 凭据主密钥和 SSH 私钥使用独立受限文件。
- Docker 中 Secret 目录只读挂载，文件必须可由 uid 10001 读取且不向其他用户开放。
- 平台和访问子域名使用 HTTPS；安全 Cookie 保持启用。
- 复杂设备后台配置 wildcard DNS、可信证书、反向代理和 `access_domain`。
- 生产在 SMTP、恢复路径和主密钥备份通过验收后显式开启 MFA。

## 备份

系统管理员通过平台接口下载 SQLite 一致性快照。备份包含业务配置、密码哈希、凭据引用和节点凭据密文，按敏感数据保护。

必须与 SQLite 成组备份但不会包含在下载文件中的资产：

- MFA 主密钥；
- 数据目录中的节点凭据主密钥 `credentials.key`；
- 基础配置和网页覆盖配置；
- SMTP 密码、API/初始化令牌；
- TLS 证书私钥；
- SSH 配置引用的服务器本地私钥文件。

## 恢复

恢复必须停服：

```bash
DMP_DB_PATH=/data/platform.db ./device-management-platform restore /backup/device-management-platform-backup.db
```

恢复命令校验 SQLite 完整性和 schema，在目标目录暂存并复核；已有数据库先生成 `.before-restore-<UTC>.db`，再原子替换并执行迁移。存在活动 WAL 共享内存文件时拒绝恢复。

MFA 主密钥和 `credentials.key` 必须与数据库快照匹配。MFA 密钥丢失时走受控重置；节点凭据主密钥丢失时密文无法恢复，需重新输入节点密码，不得通过降低安全策略绕过。
