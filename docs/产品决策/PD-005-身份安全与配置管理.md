# PD-005 身份安全与配置管理

- 状态：已接受
- 日期：2026-08-02

## 首次登录与日常认证

启用 MFA 后，首次管理员、迁移用户和管理员创建的新用户必须依次完成：修改初始密码、绑定并验证邮箱、从 TOTP 或邮箱验证码中选择一种双重认证方式。完成前不能访问业务 API。

日常登录支持密码加 TOTP、邮箱验证码或一次性恢复码。恢复码只在绑定完成时展示，服务端只保存哈希，用过即失效。

## 防锁死

- 系统管理员可重置其他用户 MFA，不能在自己的活动会话中重置自己。
- 受控主机可执行离线 `i5cloud mfa-reset <用户名>`。
- 独立平台 API 令牌保留管理员恢复入口，必须与普通登录凭据分开保管。
- schema v11 迁移保留密码和权限，但要求既有用户重新完成首次登录并撤销旧会话。

## 配置优先级

`环境变量 → 网页覆盖配置 → 基础配置文件 → 默认值`

- 环境变量接管的字段在系统设置中只读。
- 网页设置先校验完整配置，再原子写入数据卷覆盖文件，并提示重启生效。
- SMTP 密码写入独立 0600 Secret 文件；API 只返回是否已配置。
- TLS 私钥和 MFA 主密钥使用受限文件。节点账号密码与 SSH 账号密码允许从 HTTPS 界面写入，由后端使用 AES-256-GCM 加密后保存到 SQLite；API 只返回“已配置”，编辑界面始终留空。SSH 私钥只保存服务器本地文件路径。
- 节点凭据主密钥 `i5cloud.secrets.key` 使用 0600 权限独立保存，必须与 SQLite 备份成组恢复；这样既不把密文和解密密钥放在同一数据库，也不需要逐节点重新配置。
- 开发配置可关闭 MFA 以便调试，但不能删除已绑定数据；生产必须在 SMTP、恢复和主密钥备份验收后显式启用。
